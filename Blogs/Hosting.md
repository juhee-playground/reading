호스팅 공급자가 공간을 내어주면 거기에 웹 사이트를 호스팅 할 수 있다.

서버: 전세계 이용자들을 내 사이트에 연결해주는 장치

[관련링크](https://www.namecheap.com/guru-guides/what-is-web-hosting)

## 기본 개념

### 1. 웹 호스팅이란 무엇인가요?

웹사이트를 인터넷에서 볼 수 있도록 서버 공간을 제공하는 서비스
웹 사이트를 저장하고 관리할 수 있는 서버 공간을 제공.

### 2. 웹 호스팅이 필요한 이유는 무엇인가요?

개인 컴퓨터에 웹사이트를 호스팅할 수도 있지만, 24시간 가동하고, 빠른 인터넷 연결, 보안, 데이터 백업 등 기술적인 요구 사항을 충족하기 어렵다.웹 호스팅 서비스는 이러한 기술적 요구 사항을 해결하고, 웹사이트를 안정적으로 유지하는 역활을 합니다.

### 3. 웹 호스팅과 도메인은 어떤 차이가 있나요?

웹 호스팅은 웹사이트의 집이고, 도메인은 그 집으로 찾아가는 주소입니다.
둘은 별도로 구매할 수 있지만, 함께 설정해야만 웹사이트가 정상적으로 작동합니다.

1. 웹 호스팅(Web Hosting):

- 웹사이트 파일(HTML, 이미지, 동영상 등)을 저장하고 인터넷을 통해 사용자에게 제공하는 서버 **공간**입니다.
- 웹 호스팅 서비스 제공업체는 안정적인 서버 운영, 데이터 백업, 보안 등을 관리하여 웹사이트가 24시간 접근 가능하도록 보장합니다.

2. 도메인(Domain):

- 도메인은 사용자가 웹사이트에 접속하기 위해 입력하는 **“주소”**입니다.
- 예를 들어, www.example.com 같은 형태로, 웹 호스팅 서버에 연결되어 해당 서버의 데이터를 사용자에게 전달합니다.

## 웹 호스팅의 종류

### 4. 공유 호스팅과 전용 서버 호스팅의 차이는 무엇인가요?

공유 호스팅

- 하나의 서버를 여러 사용자가 공유하는 방식.
- CPU, 메모리, 대역폭 같은 서버 자원을 여러 사용자와 나눠서 사용하므로 비용이 저렴.
- 공유 호스팅은 호텔처럼 공용 공간을 사용하는 것입니다. 방의 구조를 마음대로 바꿀 수 없으며, 다른 사용자와 자원을 공유하기 때문에 제한적.
- 개인 블로그나 소규모 웹사이트

전용 서버 호스팅

- 하나의 서버를 특정 사용자에게 전적으로 제공하는 방식.
- 서버의 자원을 독점적으로 사용하며, 필요에 따라 설정, 소프트웨어 설치, 최적화 등을 자유롭게 변경할 수 있다.
- 전용 서버는 아파트처럼 독립적인 공간입니다. 내부 구조나 가구 배치를 원하는 대로 바꿀 수 있으며, 다른 사용자와 자원을 공유하지 않기 때문에 더 안정적이고 유연.
- 대규모 트래픽을 처리하거나 보안 및 성능이 중요한 대기업 사이트.

### 5. VPS(가상 사설 서버)와 클라우드 호스팅의 차이점은 무엇인가요?

VPS(가상 사설 서버)

- 구조: 물리적 서버를 여러 개의 가상 서버로 분할하여 각 사용자에게 할당하는 방식.
  각 VPS는 독립적인 운영 환경(자신만의 CPU, 메모리, 스토리지)을 갖지만, 기본적으로 물리적 서버 자원을 공유합니다.
- 확장성: 자원은 물리적 서버의 한계를 벗어날 수 없으므로 확장이 제한적.
- 비용: 일반적으로 클라우드 호스팅보다 저렴합니다.
- 장점: 비용 효율적이며, 작은 규모의 웹사이트나 특정 트래픽 수준에서 안정적으로 작동.
- VPS는 한 건물 안에 여러 독립된 아파트가 있는 구조와 비슷합니다. 각 아파트는 독립적으로 작동하지만, 건물 자체 자원을 공유합니다.

클라우드 호스팅

- 구조: 여러 대의 물리적 서버가 네트워크를 통해 연결된 “클라우드” 환경에서 리소스를 제공.
  사용자는 특정 서버에 의존하지 않고, 필요에 따라 여러 서버의 자원을 동적으로 활용합니다.
- 확장성: 리소스를 거의 무제한으로 확장하거나 줄일 수 있는 유연성을 제공. 갑작스러운 트래픽 증가에도 안정적으로 대응 가능.
- 비용: 사용한 리소스만큼 비용을 지불하는 종량제 방식을 제공하므로 효율적.
- 장점: 고가용성(High Availability), 확장성, 높은 안정성을 제공하며 대규모 웹사이트나 불규칙한 트래픽을 처리하는 데 적합.
- 클라우드 호스팅은 필요한 만큼 전력을 끌어다 쓰는 스마트 그리드와 같습니다. 특정 서버에 국한되지 않으며, 필요한 만큼만 자원을 사용 가능.

### 6. 무료 호스팅과 유료 호스팅의 장단점은 무엇인가요?

| 요소               | 무료 호스팅             | 유료 호스팅              |
| ------------------ | ----------------------- | ------------------------ |
| **비용**           | 무료                    | 월/연 단위 비용 발생     |
| **광고 삽입**      | 제공업체 광고 삽입 가능 | 광고 없음                |
| **도메인**         | 서브도메인 제공         | 커스텀 도메인 사용 가능  |
| **자원 제한**      | 스토리지 및 대역폭 제한 | 유연하게 확장 가능       |
| **기술 지원**      | 기술 지원 제한적        | 24/7 전문 기술 지원 제공 |
| **신뢰성(Uptime)** | 낮음                    | 높은 가동률 보장         |
| **보안**           | 제한적                  | 고급 보안 옵션 제공      |

## 기술적인 질문

### 7. 웹 호스팅에서 데이터 저장소와 대역폭은 무엇을 의미하나요?

- 서버(Server): 파일을 저장하고 제공하는 컴퓨터.
- **대역폭(Bandwidth)**: 사용자가 웹사이트에 접속하여 데이터를 다운로드할 수 있는 용량.
- **스토리지(Storage)**: 서버에 저장할 수 있는 데이터의 양.
- 도메인(Domain): 사용자가 웹사이트에 접근하는 주소 (예: www.example.com).

### 8. SSL 인증서란 무엇이며 왜 중요한가요?

Secure Sockets Layer의 약자로, 웹사이트와 사용자의 브라우저 간 데이터를 암호화하여 안전하게 전송되도록 보장하는 디지털 인증서입니다. 이는 사용자가 웹사이트에 입력한 민감한 정보(예: 로그인 정보, 신용카드 번호)가 제3자에게 노출되지 않도록 보호.

SSL 인증서의 주요 기능

- 데이터 암호화: 클라이언트(브라우저)와 서버 간 데이터가 암호화되어 전송 중 도청이나 중간자 공격을 방지합니다.
- 인증 및 신뢰성 제공: SSL 인증서는 웹사이트 소유자를 검증하여 사용자가 신뢰할 수 있는 사이트임을 보장합니다.
- 데이터 무결성: 전송 중 데이터가 변조되지 않도록 보호합니다.

SSL 인증서가 중요한 이유

- 보안 강화: SSL은 민감한 데이터를 보호하므로, 사용자 정보 유출을 방지할 수 있습니다. 특히, 전자상거래 사이트나 로그인 페이지에서 필수적.
- SEO(검색엔진 최적화) 향상: 구글은 SSL이 적용된 웹사이트(HTTPS)를 더 높은 순위로 평가.
- 사용자 신뢰도 향상: 브라우저 주소창에 “자물쇠 아이콘” 또는 “HTTPS”가 표시되면 사용자가 더 신뢰를 가지게 됨.
- 법적 및 규제 요구사항 준수: 많은 국가 및 산업에서는 SSL을 데이터 보호의 필수 요소로 요구.
- 브랜딩 및 전문성 강화: SSL 인증서는 회사나 브랜드가 보안에 신경을 쓰고 있음을 사용자에게 보여줌.

요즘은 선택이 아닌 필수

### 9. 호스팅 서버의 위치가 웹사이트 속도에 어떤 영향을 미치나요?

- 네트워크 지연(Latency): 데이터가 서버에서 사용자에게 도달하는 데 걸리는 시간. 서버가 사용자의 위치와 멀리 떨어져 있을수록 데이터가 이동하는 물리적 거리가 길어지고, 전송 시간이 늘어남.
- 라우팅 및 인터넷 트래픽: 데이터가 사용자에게 도달하기 위해 거치는 네트워크 노드(라우터)의 수와 경로도 영향을 미침. 서버와 사용자가 멀리 떨어져 있으면 더 많은 네트워크 노드를 거칠 가능성이 높아짐.
- 국가별 인터넷 인프라: 서버와 사용자가 다른 국가에 위치하면 해당 국가의 인터넷 인프라 품질도 웹사이트 속도에 영향을 줌.

## 트렌드와 발전

### 10. 클라우드 호스팅이 점점 더 인기를 끌고 있는 이유는 무엇인가요?

더 유연하고 효율적인 자원 관리와 뛰어난 성능을 제공하기 때문에

- 뛰어난 확장성(Scalability)

  - 클라우드 호스팅은 필요에 따라 자원을 동적으로 조정.
  - 트래픽이 급증할 때 추가 CPU, 메모리, 대역폭을 신속히 할당 가능.
  - 트래픽 감소 시 자원을 줄여 비용 절감.
  - 전통적인 서버 호스팅에서는 하드웨어 업그레이드가 필요하지만, 클라우드 호스팅은 소프트웨어적으로 처리.

- 고가용성(High Availability)

  - 클라우드 호스팅은 여러 대의 서버로 구성된 네트워크를 사용.
  - 특정 서버가 장애를 일으키더라도, 다른 서버가 대체 역할을 하여 웹사이트 다운타임을 최소화.
  - 전통적인 단일 서버 환경에 비해 안정성과 신뢰성이 매우 높음.

- 비용 효율성(Cost Efficiency)

  - 클라우드 호스팅은 사용한 리소스에 대해서만 비용을 지불하는 **종량제(Pay-as-you-go) 모델**을 제공합니다.
  - 초기 비용이 높은 물리적 서버 구매와 유지 비용을 절감할 수 있습니다.

- 글로벌 접근성과 빠른 속도

  - 클라우드 호스팅 제공업체는 전 세계에 분산된 데이터 센터를 운영.
  - 사용자는 자신에게 가까운 데이터 센터에서 데이터를 전송받아 더 빠른 로딩 속도를 경험.
  - CDN(Content Delivery Network)과 결합하여 전 세계적으로 일관된 성능을 제공.

- 보안 강화

  - 클라우드 호스팅 제공업체는 최신 보안 기술과 프로토콜을 통해 데이터를 보호.
  - DDoS 공격 방어, 자동 데이터 백업, 암호화된 연결(SSL) 등을 기본으로 제공.
  - 데이터를 분산 저장하기 때문에 단일 서버 장애로 인한 데이터 손실 위험이 줌.

- 손쉬운 관리 및 자동화

  - 클라우드 호스팅은 간단한 인터페이스와 대시보드를 통해 서버 리소스, 트래픽, 보안 등을 실시간으로 관리.
  - 자동 백업, 자동 확장 기능 등을 제공하여 관리 부담을 줄임.

- 환경 친화적(Eco-Friendly)

  - 클라우드 호스팅은 물리적 서버 사용량을 최적화하여 에너지 소비를 줄임.
  - 여러 사용자가 자원을 공유하므로 자원의 낭비가 감소.

- 최신 기술 지원
  - 클라우드 호스팅은 최신 기술과 완벽하게 호환.
  - 머신러닝, AI, IoT(사물 인터넷) 등의 기술을 활용하는 프로젝트에 적합.
  - Kubernetes, Docker 등 컨테이너 기반 워크로드도 손쉽게 관리 가능.

### 11. 서버리스 컴퓨팅이 전통적인 호스팅 방식과 어떤 차이가 있나요?

#### 정의

- **전통적인 호스팅:**

  - 사용자가 물리적 서버 또는 가상 서버(VPS)를 임대하여, 해당 서버를 설정, 운영, 유지보수하는 방식입니다.
  - **예:** 공유 호스팅, 전용 서버 호스팅, 클라우드 호스팅.

- **서버리스 컴퓨팅:**
  - 서버 관리 부담을 없애고, 애플리케이션 실행에 필요한 코드만 작성하면 클라우드 제공업체가 나머지 작업(서버 관리, 확장 등)을 처리하는 방식입니다.
  - **예:** AWS Lambda, Google Cloud Functions, Azure Functions.

#### 요약 비교표

| 요소          | 전통적인 호스팅                | 서버리스 컴퓨팅             |
| ------------- | ------------------------------ | --------------------------- |
| **서버 관리** | 사용자가 직접 관리             | 제공업체가 관리             |
| **비용 구조** | 고정 요금                      | 종량제(사용한 만큼 지불)    |
| **확장성**    | 수동 확장                      | 자동 확장                   |
| **응답 시간** | 항상 짧음(서버 가동 상태 유지) | 초기 요청 시 지연 발생 가능 |
| **사용 사례** | 고정 트래픽, 복잡한 설정 필요  | 이벤트 기반, 간헐적 트래픽  |
| **유연성**    | 높은 서버 제어권               | 환경 설정 제한적            |
